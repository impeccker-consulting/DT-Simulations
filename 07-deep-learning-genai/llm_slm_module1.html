Every token becomes a list of numbers.

Click any token above (or one below) and the model turns it into a vector — a coordinate in "meaning space." Words used in similar contexts end up near each other, which is how a model knows "revenue" and "profit" are cousins, and "revenue" and "banana" are not.

03 — Prediction

Every response is just "what token comes next?" — repeated.

An LLM has no plan, no outline, no intent. At each step it ranks every possible next token by probability, then picks one. Choose a starter phrase, adjust temperature, and hit sample to see the model roll its dice.

05 — Training

None of this is programmed. It's learned, in two stages.

Nobody hand-wrote rules for what comes after "revenue came in..." The model earned that skill in two distinct phases of training, months apart, with very different goals.

Stage 1
Pretraining — learning the shape of language
The model reads a vast slice of the internet, books, and code — trillions of tokens — with one repeated task: predict the next token, check the answer, adjust, repeat. No teacher, no labels, no instructions. This is where it absorbs grammar, facts, and reasoning patterns as a side effect of getting really good at prediction.
Stage 2
Fine-tuning & alignment — learning to be useful
A pretrained model only continues text — it doesn't know it's supposed to answer questions or follow instructions. Humans then show it examples of good responses, and rank its answers against each other (RLHF), nudging it from "predicts plausible text" toward "gives helpful, safe, on-task answers."

08 — Architecture

Reading and writing are different jobs — some models split them.

Modules 03 and 04 showed a model generating text strictly left to right, one token at a time. That's not accidental — it's a specific architectural choice called a decoder. There's another way to process language entirely, called an encoder. Knowing the difference tells you what a model is actually built to do.

Encoder-only
e.g. BERT, RoBERTa
Reads the whole input at once, in both directions, and outputs an understanding of it — not new text. Built for classification, search relevance, sentiment tagging.
Decoder-only
e.g. GPT, Claude, Llama, Gemini
Generates text left to right using causal attention only — exactly what modules 03 and 04 showed you. This is what powers almost every modern chat assistant, including the one you're using right now.
Encoder–decoder
e.g. T5, the original 2017 Transformer, most translation systems
An encoder fully reads the source text; a decoder then generates the output while continuously glancing back at that encoded source.
